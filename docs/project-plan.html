01범위와 전제

무엇을 만들고, 무엇을 만들지 않는지를 먼저 못 박는다. 9주 안에 끝나는 프로젝트에서 가장 흔한 실패는 기술이 아니라 범위다.

IN이번에 만드는 것

  • 단일 셀 — 스토커 1대, 로드포트 1개, 로봇 1대. 멀티 로봇 스케줄링은 범위 밖
  • 트레이 1종 + 변형 — 기준 JEDEC 트레이 1종을 CAD로 모델링하고, 치수·색·마찰만 랜덤화
  • 풀사이클 1회전 — 오더 수신에서 도킹 복귀까지, 실패 복구 3종 포함
  • 학습 기반 파지 — 기하 프라이어 + 잔차 정책, baseline 대비 개선폭 측정

OUT이번에 하지 않는 것

  • 실제 클린룸 규격(파티클·ESD·SEMI 인증) 충족 — 시나리오의 근거로만 인용
  • MES / OHT 상위 시스템 연동 — 오더는 목업 토픽으로 주입
  • 트레이 안의 개별 칩 단위 취급 — 운반체 레벨까지만
  • 웨이퍼·FOUP — 후공정 부품 캐리어와 취급 규격이 다르다
전제 확인 필요

목표 문장이 "핵심 파지 단계는 "에서 끊겨 있어, 학습 기반(잔차 정책) 파지로 가정하고 아래를 설계했습니다. 순수 강화학습 end-to-end나 고전 모델 기반으로 가려면 04장 설계가 통째로 바뀌므로, 이 한 줄만 먼저 확정해 주세요.

03알고리즘 스택

레이어별로 무엇을 쓰고, 왜 그것을 쓰는가. 이 도메인에만 있는 제약이 선택을 바꾸는 지점을 표시했다.

L1인식 — 탐색 공간을 먼저 줄인다

랙은 CAD가 있고 도킹 포즈도 알고 있다. 그러니 슬롯 위치는 사전 계산해서 ROI로 쓰고, 네트워크에게는 "이 좁은 창 안에 트레이가 있는가, 있다면 얼마나 틀어졌는가"만 묻는다. 일반 bin-picking처럼 장면 전체를 훑는 설계는 이 도메인에서 낭비다.

  • 슬롯 ROI 산출 — 랙 CAD + 정렬된 베이스 포즈로 슬롯별 이미지 창 계산
  • 점유 판정 — ROI별 이진 분류 (빔·비어있음·이물)
  • 6D 포즈 — 평면 RANSAC으로 상면 추출 → PCA로 장·단축 → CAD 정합(ICP)으로 정밀화
  • 대칭 모호성 — JEDEC 트레이는 180° 회전 대칭이다. 파일럿 홀·모따기 같은 비대칭 피처로 방향을 확정하고, 확정 실패 시 두 후보를 모두 유효로 넘긴다
이 도메인 고유의 함정

검정 트레이는 depth 센서에 잘 안 잡힌다. JEDEC 트레이는 카본 충진 흑색 플라스틱이라 IR 반사율이 낮고, 구조광·ToF 센서에서 depth hole이 뚫린다. 이걸 모르고 시뮬에서 완벽한 depth로 학습하면 실물에서 그대로 무너진다.

대응은 두 갈래다. (1) 센서 쪽 — 스테레오 RGB 병용, 액티브 패턴 프로젝터, 측면 조명. (2) 시뮬 쪽 — Isaac Sim 합성 depth에 반사율 기반 dropout 노이즈를 일부러 주입해서 학습한다. 두 번째가 이 프로젝트에서 반드시 해야 할 일이고, 발표에서 설명할 가치가 가장 큰 디테일이다.

L2모션 — 트레이는 기울이면 안 되는 화물이다

일반 픽앤플레이스와 결정적으로 다른 점: 트레이 위에는 고정되지 않은 부품이 얹혀 있다. 경로 계획에 두 개의 제약이 추가로 붙는다.

  • 자세 제약 — 이송 중 기울기 ≤ 5°. MoveIt 2의 orientation constraint로 선언
  • 가속도 상한 — 부품이 미끄러지지 않을 조건은 a_max < μg. μ≈0.3이면 약 2.9 m/s²이고, 안전계수 0.5를 곱해 1.4 m/s²를 스케일링 상한으로 쓴다
  • 충돌 모델 — 랙의 얇은 슬롯 격벽은 포인트클라우드로 잡히지 않는다. octomap이 아니라 CAD collision object로 씬에 넣어야 한다
  • 접근·후퇴는 직선(Cartesian path), 그 밖은 RRTConnect 또는 cuMotion

L3내비게이션과 도킹 — 정밀도를 기구가 아니라 인식으로 얻는다

AMR의 반복 정지 정밀도는 통상 ±10–30 mm다. 파지에 필요한 정밀도는 그보다 한 자리 작다. 따라서 "매번 같은 자리에 선다"를 가정하지 않는 것이 설계 원칙이다. Nav2로 대략 접근한 뒤, 마커 기반 시각 서보로 ±3 mm까지 좁히고, 남은 오차는 L1 인식이 흡수한다.

L4오케스트레이션 — FSM이 아니라 Behavior Tree

단계는 6개지만 복구 분기가 그만큼 더 있다. 상태 머신으로 짜면 전이 개수가 제곱으로 늘고, 재시도 횟수 같은 상태가 코드 여기저기에 흩어진다. BehaviorTree.CPP의 Fallback / RetryUntilSuccessful 데코레이터는 이 재시도 구조를 선언적으로 표현하고, Nav2가 이미 같은 스택을 쓰므로 학습 비용도 공유된다.

  • 블랙보드 키 — tray_id, source_slot, target_port, grasp_pose, retry_count
  • 각 단계는 ROS 2 액션 서버 하나로 대응 (취소·피드백이 필요하므로 서비스가 아니다)

L5안전

  • ISO/TS 15066 속도·분리 모니터링 — 사람 1.5 m 이내 감속, 0.5 m 이내 정지
  • 트레이 낙하 감지 — 그리퍼 힘 급변 + 비전 재확인, 감지 즉시 정지 후 알림
  • 비상정지·센서 고장 시나리오를 시뮬에서 주입 테스트로 검증 (실물로는 못 하는 검증이 트윈의 값어치다)

04파지 설계 — 학습은 어디에 들어가는가

"학습 기반 파지"라는 말은 세 가지 완전히 다른 설계를 뜻할 수 있다. 셋을 비교하고, 왜 세 번째를 고르는지 적는다.

왜 C인가 — 9주 프로젝트 기준

기준A 모델 기반B 순수 학습C 잔차
필요 데이터량0수십만 롤아웃수천 롤아웃
안전 경계명시적없음클립으로 명시적

C의 결정적인 장점은 baseline이 공짜로 딸려온다는 것이다. 잔차를 0으로 두면 그게 곧 A이므로, "명목 포즈 단독 vs 잔차 보정"을 같은 코드·같은 시나리오로 비교할 수 있다. 발표에서 주장할 수 있는 숫자가 바로 이 차이다.

정책 입출력

  • 입력 — 명목 파지 포즈 기준으로 크롭·정렬한 depth 패치 (64×64) + RGB 패치 + 명목 포즈 6D
  • 출력 — 잔차 Δ(x, y, z, roll, pitch, yaw) 6채널 + 파지 성공 확률 s
  • 선택 — 후보 3개 중 s 최대를 실행. 최대값이 τ=0.6 미만이면 시점을 바꿔 재스캔
  • 라벨 — Isaac Sim에서 자동 판정. 리프트 5 mm 후 트레이가 그리퍼에 유지되고 기울기 ≤ 5°면 성공

05인터페이스 계약

2인이 병렬로 일하려면 코드보다 인터페이스가 먼저다. 1주차에 이것부터 고정하고 시작한다.

# tray_msgs/action/PickTray.action  — 인식·학습(A)과 모션·통합(B)의 경계
string                     tray_id
uint8                      slot_index
geometry_msgs/PoseStamped  rack_frame        # 정렬 완료된 베이스 기준
---
bool                       success
uint8                      fail_code         # 0 OK · 1 NOT_FOUND · 2 LOW_CONF
                                             # 3 SLIP · 4 COLLISION · 5 TIMEOUT
geometry_msgs/Pose         executed_grasp
float32                    grasp_score       # 정책 출력 s
float32                    cycle_time_s
---
uint8                      phase             # SCAN·PLAN·APPROACH·CLOSE·LIFT·RETREAT
float32                    progress

fail_code를 정수로 못 박아 두면 평가 하네스가 실패 원인별 통계를 자동으로 뽑을 수 있다. 07장 지표 표의 대부분이 이 필드 하나에서 나온다.

패키지 구조

src/
  tray_msgs/         # 액션·메시지 — 1주차에 먼저 확정 (공통)
  tray_sim/          # USD 씬, Isaac 스크립트, 랜덤화   (공통)
  tray_perception/   # 검출·6D 포즈                    (Track A)
  tray_grasp/        # 잔차 정책, 학습·추론             (Track A)
  tray_motion/       # MoveIt 2 래퍼, 제약·힘 제어      (Track B)
  tray_nav/          # Nav2 설정, 마커 도킹             (Track B)
  tray_bt/           # Behavior Tree, 오케스트레이션    (Track B)
  tray_eval/         # 평가 하네스, 리포트 생성         (공통)

06개발 로드맵

각 페이즈는 "무엇을 만든다"가 아니라 "무엇이 측정되면 끝난 것인가"로 닫는다. Done 기준이 없는 페이즈는 영원히 끝나지 않는다.

PHASE 01주차

트윈 뼈대 세우기

씬과 통신 경로를 먼저 살린다. 이 단계에서 막히면 뒤가 전부 밀리므로, 알고리즘은 한 줄도 쓰지 않는다.

  • USD 씬 — 스토커 랙, JEDEC 트레이, 로드포트, 로봇
  • ROS 2 브릿지 — /joint_states, /camera/depth, /camera/color
  • tray_msgs 확정 및 머지
Done실물과 동일한 토픽 이름·타입으로 시뮬 로봇이 관절 명령을 수행한다
PHASE 12주차

결정론적 픽앤플레이스

인식을 빼고 포즈를 시뮬레이터 GT로 직접 주입해서, 모션만 먼저 완성한다. 인식과 모션의 버그를 섞지 않기 위한 순서다.

  • MoveIt 2 자세 제약(≤5°) · 가속도 상한(1.4 m/s²) 적용
  • 랙을 CAD collision object로 등록, 슬롯 간섭 없이 진입
DoneGT 포즈 기준 20회 중 20회 성공 · 사이클타임 기록 확보
PHASE 23–4주차

인식 파이프라인

합성 데이터를 만들고 6D 포즈까지 연결한다. depth dropout 노이즈 모델을 이 단계에서 넣어야 뒤가 유효하다.

  • 도메인 랜덤화 롤아웃으로 데이터셋 생성 (라벨은 시뮬 GT)
  • 슬롯 점유 판정 → 6D 포즈 → /tray_poses 발행
  • 대칭 모호성 해소 로직 검증
Done포즈 오차 중앙값 ≤ 3 mm / 2° · 검출 재현율 ≥ 95 %
PHASE 35–6주차

학습 기반 파지  ·  프로젝트의 주장

잔차 정책을 학습하고, 반드시 baseline과 나란히 놓고 측정한다. 여기서 나오는 개선폭 하나가 이 프로젝트의 결론이다.

  • 명목 포즈에 ±8 mm / ±5° 오차를 고의로 주입한 교란 조건 구성
  • baseline(잔차 0) vs 잔차 정책, 동일 시드·동일 시나리오로 비교
  • 실패 원인을 fail_code별로 분해해 무엇이 개선됐는지 특정
Done교란 조건에서 baseline 대비 성공률 향상이 통계적으로 유의 · 실패 원인 분해표 확보
PHASE 47–8주차

풀사이클 통합

내비게이션·도킹·BT를 붙여 02장의 사이클을 닫는다. 정상 경로보다 복구 분기 검증에 시간을 더 쓴다.

  • BT 구성, 액션 서버 6종 연결
  • 실패 주입 테스트 — 파지 실패 / 정렬 실패 / 삽입 걸림
Done연속 10사이클 무개입 완주 · 주입한 실패 3종 모두 자동 복구
PHASE 59주차

sim-to-real 격차 측정과 발표

실물 로봇으로 옮길 수 있는 범위까지 옮기고, 격차를 숨기지 않고 수치로 낸다. 격차 표 자체가 결과물이다.

  • 동일 시나리오를 실물에서 재현 (가능한 하위 집합)
  • sim 성공률 − real 성공률, 원인 분해

범위 방어선

Phase 3까지가 최소 성공선(MVP)입니다. 일정이 밀리면 Phase 4의 내비게이션을 먼저 잘라내세요 — "고정 베이스에서의 인식·파지"만으로도 완결된 주장이 됩니다. 반대로 파지 학습을 잘라내면 프로젝트의 주장 자체가 사라지므로, 이쪽은 건드리지 않습니다.

08리스크

실패가 예상되는 지점과, 그것을 언제 발견할 것인가. 발견 시점을 앞당기는 것이 완화책의 본질이다.

리스크왜 생기나완화발견 시점

접촉 동역학 격차 마찰·강성 파라미터 부정확 μ 랜덤화 · 힘 임계 기반 조기 중단 Phase 5
학습 개선폭이 미미 기하 파이프라인이 이미 충분히 정확 교란 폭을 키워 유의미한 구간에서 비교 · 그래도 없으면 "불필요함"을 결론으로 보고 Phase 3
범위 초과로 미완 내비게이션·통합이 예상보다 큼 Phase 3 = MVP 선언 · Phase 4부터 절삭 가능하게 설계 상시

맨 아래에서 두 번째 항목은 리스크라기보다 정직한 결과의 한 형태다. "잘 만든 기하 파이프라인 앞에서는 학습이 필요 없었다"도 근거만 있으면 훌륭한 결론이며, 그걸 말하려면 baseline 비교 구조가 처음부터 있어야 한다 — 04장에서 C를 고른 이유가 여기에도 걸린다.

091주차 착수

2인 병렬 작업의 출발점. 인터페이스를 먼저 고정하고, 그 다음 각자의 트랙으로 갈라진다.

  • 대상 트레이 1종 확정 — 치수·재질·파지 가능면을 수치로 적고 CAD 작성공통
  • tray_msgs 정의 머지 — 05장 액션 계약을 확정. 이게 끝나야 병렬 작업이 시작된다공통
  • USD 씬 초안 — 랙 · 트레이 · 로드포트 · 로봇 배치공통
  • ROS 2 브릿지 확인 — 관절 명령 왕복, 카메라 토픽 수신Track B
  • 합성 데이터 파이프라인 뼈대 — 랜덤화 파라미터 목록부터 코드로Track A
  • 평가 하네스 스텁 — 롤아웃 N회 실행 → fail_code 집계 → CSV공통
  • 목표 문장 확정 — 01장 노트의 잘린 부분을 채워 README에 한 문장으로 고정공통
