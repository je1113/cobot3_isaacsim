# 도킹스테이션 구현 (feature/docking, 2026-09-28)

로봇이 **place 를 마친 뒤 배터리(가동시간)가 일정 수준을 넘었으면 다음 작업(스택 회수 · 복귀 순찰)을 하지 않고 도킹스테이션에 가서 충전**하는 기능이다. 이 문서는 그날 결정한 사항과, 그 결정을 코드로 옮기며 **무엇을 어디에 새로 정의했는지** 를 적는다. 코드 주석이 "왜" 를 각자 들고 있고, 이 문서는 전체 지도다.

브랜치: `feature/docking` (feature/grasp 에서 분기). 설계 근거: `docs/02_2, 3차 목표 설계도.html` §2 · §4, `NavigateTo.action` 머리주석("배터리 타이머").

---

## 0. 한눈에 보기

```
PLACE 성공
   └─ [?] 복귀 경로 (Selector, memory=True)
        ├─ [→] 충전 복귀   ← 가동 15분(soft_threshold_s=900) 넘었다
        │     충전 필요? → DOCK_NAV → DOCK_IN → DOCK → DOCK_OUT → 충전 완료
        └─ [→] 그냥 복귀   ← 안 넘었다 (지금까지와 동일. 임시 강제 스택 회수만)
   └─ RETURN (Nav2 → patrol_route[0]) → 사이클 완료 → 순찰
```

- **배터리 = 가동시간 타이머.** Isaac 씬에 배터리가 없어서 "첫 출발(START 성공)부터 흐른 시간" 이 배터리다. 충전이 끝나면 0 으로 되돌린다.
- **도크 = 맵 처음 위치.** 씬 스폰 위치 · Nav2 AMCL initial_pose · 옛 launch 의 DOCK_ROUTE 마지막 점이 전부 같은 점이다. 로봇 두 대 자리가 `ParkingPad` 위에 0.98 m 간격으로 고정돼 있다. 자리 다툼(선점)은 없다.
- **진입은 전진, 이탈은 후진.** Nav2 는 도크 2 m 앞 대기점까지만, 마지막 2 m 는 `patrol_to`(cmd_vel 직진). 나올 때 같은 선을 후진으로 되짚는다. 도크 구역 안에서는 회전하지 않는다.
- **"return 을 안 한다" 는 불가능.** 순찰 잎은 직선 cmd_vel 주행이라 반드시 `patrol_route[0]` 에서 출발해야 한다. 그래서 충전 뒤에는 항상 RETURN(Nav2)이 따라온다. 도킹은 RETURN 을 **대체** 하는 것이 아니라 그 **앞에 끼는** 것이다.
- **충전 중에는 웹 작업(ExecuteTask goal)을 거절.** 웹은 그 거절을 경보 없이 대기시키고, RECOVER 는 상대 로봇에게 넘긴다.

## 1. 결정 사항 (사용자 결정, 2026-09-28)

| # | 항목 | 결정 |
|---|---|---|
| 1 | 도킹을 어디에 끼우나 | **A + B 둘 다.** A: 미션 안, PLACE 직후 "복귀 경로" Selector. B: 최상위 "충전(대기 중)" 가지 — 순찰만 오래 한 로봇 · wait_for_task 대기 · RECOVER 를 마친 로봇을 잡는다 |
| 2 | STACK_PLACE(RECOVER) 뒤에도 검사하나 | **한다.** B 가 자동으로 잡는다(RecoverDone 뒤 로봇은 미션 밖이다) |
| 3 | 타이머 시작점 | **START 성공(첫 출발) 시점.** robot2 의 출발 대기 60 s 는 안 센다. 순찰 대기(wait_for_task) 시간은 **센다** |
| 4 | 충전 중 웹 goal | **거절.** 로봇 상태에 `dock` 계열 값을 추가하고, 그 상태면 ExecuteTask 를 안 받는다. STOP · PAUSE(RobotCommand)는 안전을 위해 그대로 먹는다. 웹은 상태가 `dock*` 인 동안의 거절을 **경보 없이 대기**, **RECOVER 는 상대 로봇 큐 맨 앞으로 이동** |
| 5 | 진입 방식 | **전진 진입(yaw 0°) + 후진 이탈.** Nav2 → 2 m 앞 대기점, patrol_to 직진 2 m → 도크, 충전, patrol_to 후진 2 m → 대기점, Nav2 RETURN |
| 6 | 숫자 | `soft_threshold_s` **900** (15분) · `charge_duration_s` **60** (1분) · `hard_threshold_s` **0** (미사용 — 캐리어를 든 채 끊지 않는다) · DOCK 잎 timeout = charge + 60 |

기본값으로 둔 것(이견 없었음): 강제 스택 회수는 충전 필요 시 건너뜀 · `_recover_ok_now` 가 충전 필요 시 RECOVER 거절 · Dock 취소/실패 시 타이머 리셋 안 함(부분 충전 불인정) · 도킹 단계는 DB(magazine_log/stack_log)에 안 남김 · docking_server 는 새 패키지 `cobot3_docking` · 두 대 동시 도킹의 상대 대기 조율은 1차에서 제외.

## 2. 새로 만든 인터페이스 — `Dock.action`

**파일** `src/cobot3_interfaces/action/Dock.action` (CMakeLists.txt 의 `rosidl_generate_interfaces` 에 등록)

| 방향 | 이름 | 뜻 |
|---|---|---|
| 보내는 쪽 | `cobot3_orchestrator/task_manager` (로봇마다 한 벌) | |
| 받는 쪽 | `cobot3_docking/docking_server` (**전역 1개**) | |
| 액션 이름 | `/docking/dock` (**절대이름**) | 두 task_manager 가 같은 서버를 부른다 |

```
# goal
string  robot_name          # "robot1" | "robot2" — 네임스페이스 밖 서버라 식별자를 필드로
float32 charge_target_pct   # 0 이면 100
---
# result
uint8 NONE=0  UNKNOWN_ROBOT=1  NO_CONTACT=2  TIMEOUT=3  CANCELED=4
bool    success
uint8   fail_reason         # ★ ActionLeaf 가 success=false 면 무조건 읽는다 — 이 모양이 계약
float32 charge_pct
---
# feedback
float32 charge_pct          # 0 → 100
float32 remaining_s
```

- 주행은 이 액션에 없다. 도크 앞까지 가는 것과 나오는 것은 task_manager 가 NavigateTo / patrol_to 로 한다. 이 액션은 "도착한 다음"(접점 · 충전 대기)만 맡는다.
- `PAD_BUSY` 같은 자리 다툼 사유는 **넣지 않았다.** 자리가 로봇별 고정이라 다른 로봇이 갈 경로가 없다.

## 3. 새로 만든 노드 — `cobot3_docking/docking_server`

**패키지** `src/cobot3_docking/` (ament_python. 뼈대만 있던 빈 패키지에 노드를 채웠다)
**파일** `src/cobot3_docking/cobot3_docking/docking_server.py` — `ros2 run cobot3_docking docking_server`

| 항목 | 내용 |
|---|---|
| 액션 서버 | `/docking/dock` (`Dock.action`) — `ReentrantCallbackGroup` + `MultiThreadedExecutor(4)` 로 **두 goal 동시 수락**(두 로봇이 각자 자리에서 병렬 충전) |
| 발행 | `/docking/state` (std_msgs/String) — `robot1=charging:45 \| robot2=idle` 표시용 |
| 파라미터 | `frames_yaml`(dock_pads 읽기) · `charge_duration_s`(60) · `dock_timeout_s`(0 = charge+60) · `feedback_period_s`(1.0) |
| 하는 일 | robot_name 이 `dock_pads` 에 있는지 검증 → 없으면 `UNKNOWN_ROBOT`. 있으면 `charge_duration_s × (target_pct/100)` 동안 대기하며 `charge_pct` feedback → `success`. 취소 → `CANCELED`. 한도 초과 → `TIMEOUT` |
| 안 하는 일 | 로봇을 움직이지 않는다. 자리 점유 관리를 하지 않는다 |

실기로 갈 때는 이 파일 안에서 opennav_docking 을 부르고 배터리 토픽을 보는 것으로 바꾼다. task_manager 쪽 계약(Dock.action)은 그대로다.

**함수 목록**
- `load_dock_pads(path)` — frames.yaml `dock_pads` → `{robot_name: (x, y, yaw_deg)}`
- `DockingServer._on_goal / _on_cancel / _execute` — 액션 콜백. `_execute` 가 타이머 루프
- `DockingServer._publish_state` — `/docking/state`

## 4. 설정 — `frames.yaml` 에 `dock_pads` 절 추가

**파일** `src/cobot3_bringup/config/frames.yaml` (좌표계 단일 출처)

```yaml
dock_pads:
  robot1: { xy_yaw_deg: [5.5, -6.591, 0.0], approach_m: 2.0 }
  robot2: { xy_yaw_deg: [5.5, -7.575, 0.0], approach_m: 2.0 }
```

- 근거: `simple_factory_layout.usda` 의 `nova_carter1/2` 스폰 위치 = `robot*_nav2_params.yaml` `initial_pose`. 둘 다 `/World/.../DockingZone/ParkingPad`(2.4 m × 2.4 m) 위.
- yaw 가 0 인 이유: 전진 진입(결정 5). 스폰은 180 이지만 도킹 뒤 자세는 동쪽을 본다.
- `approach_m: 2.0` — 옆자리에 상대가 주차돼 있으면 Nav2 팽창 반경(global 1.0 m)에 걸린다. 1 m 앞은 상대 차체에서 약 1.2 m 로 경계선, 2 m 면 확실히 밖. `STACK_APPROACH_CREEP_M` 과 같은 값.
- task_manager(`_resolve_dock_pose`)와 docking_server(`load_dock_pads`)가 같은 절을 읽는다. 좌표를 코드 · launch 에 다시 적지 않는다. launch 의 `DOCK_ROUTE_BY_ROBOT` 는 옛 판 기록이고 안 쓴다.

## 5. `task_manager.py` 에 추가한 것

### 5-1. 단계 상수 (`/orchestrator/state` 의 `state=` 값이자 트리 잎 이름)

| 상수 | 값 | 뜻 | 어떤 액션 |
|---|---|---|---|
| `DOCK_NAV` | `dock_nav` | Nav2 로 도크 줄 위 대기점(도크에서 approach_m 서쪽, yaw 0)까지 | `navigation/navigate_to` |
| `DOCK_IN` | `dock_in` | cmd_vel 직진 2 m → 자기 도크 자리(전진) | `navigation/patrol_to` |
| `DOCK` | `dock` | 접점 · 충전 대기 | **`/docking/dock`** |
| `DOCK_OUT` | `dock_out` | cmd_vel 후진 2 m → 대기점 (도크 구역 안 회전 금지) | `navigation/patrol_to` |
| `DOCK_RETURN` | `dock_return` | B 가지만. Nav2 → `patrol_route[0]` (A 는 기존 `RETURN`) | `navigation/navigate_to` |
| `DOCK_STAGES` | 위 다섯 튜플 | goal 거절 판정(`_docking_now`)용 | |

관련 상수: `DOCK_APPROACH_CREEP_M = 2.0`(frames.yaml approach_m 없을 때 폴백) · `DEFAULT_SOFT_THRESHOLD_S = 900` · `DEFAULT_HARD_THRESHOLD_S = 0` · `DOCK_TIMEOUT_MARGIN_S = 60` · `DEFAULT_FRAMES_YAML`.

표 갱신: `STAGE_TO_REASON`(DOCK → `dock_error`, 나머지 `nav_error`) · `TASK_STAGE`(DOCK_* → feedback.stage `"dock"`, DOCK_RETURN → `"return"`) · `TASK_PROGRESS`(0.82~0.9). **넣지 않은 표 둘**: `LOGGED_STAGES`(DB 에 안 남김 — B 경로는 run_id 가 없어 UNIQUE 제약과 충돌) · `MISSION_STAGES`(A 는 PICK 이 이미 `mission_started` 를 세워 SKIP 이 와도 충전·RETURN 까지 마친다. B 는 순찰 중 받아 둔 SCAN 작업이 있는 채로 돌 수 있어, DOCK_* 를 미션으로 잡으면 취소가 끝나지 않는 result 를 기다리게 된다).

### 5-2. 새 잎(Behaviour) 셋

| 클래스 | 자리 | 하는 일 |
|---|---|---|
| `NeedsCharge(name, node)` | 충전 가지 둘의 **문지기** (Detected · TaskKind 와 같은 자리) | `node.needs_charge()` 면 SUCCESS, 아니면 FAILURE. `dock_pose` 가 None 이면 영원히 FAILURE(좌표 없이 도킹하러 가지 않는다) |
| `MarkDeparted(name, node)` | START 성공 직후 (OneShot 안, 평생 한 번) | `node.mark_departed()` — 가동시간 타이머 시작 |
| `ChargeDone(name, node, waypoints=None, rewind=False)` | DOCK_OUT 뒤 | `node.charge_done()` — 타이머 0. `rewind=True`(B) 면 `waypoints.idx = 1` 되감기(CycleDone 과 같은 이유) |

DOCK_NAV · DOCK_IN · DOCK · DOCK_OUT · DOCK_RETURN 은 **기존 `ActionLeaf` + `Freeze`** 를 그대로 쓴다(새 클래스 없음). 실패하면 Freeze 가 얼려 그 자리에 정지하고 `/orchestrator/resume` 으로 푼다 — 기존 실패 정책 그대로.

### 5-3. `build_tree` 변경

- **`dock_leg(tag)` 팩토리** — `[DOCK_NAV, DOCK_IN, DOCK, DOCK_OUT]` 한 벌을 만든다. py_trees 잎은 트리에서 한 자리만 차지하므로 A · B 에 한 벌씩(`tag=""`, `tag="(대기)"`). 목표 좌표는 `node.dock_pose` · `_back_off(dock_pose, node.dock_approach_m)` 을 tick 시점에 읽는다.
- **A — 미션 안 "복귀 경로"** (PLACE → CREEP_OUT 뒤, RETURN 앞)
  ```
  Selector("복귀 경로", memory=True)
    ├─ Sequence("충전 복귀")  = [NeedsCharge] + dock_leg("") + [ChargeDone]
    └─ Sequence("그냥 복귀")  = [(임시) 강제 스택 회수]  또는 [Success]
  ```
  memory=True 인 이유는 배송 Selector 와 같다 — 한 번 고른 가지를 끝까지 든다. 충전이 필요하면 강제 스택 회수도 건너뛴다.
- **B — 최상위 "충전(대기 중)"** (우선순위 Selector: `회수 처리 → 캐리어 처리 → 충전(대기 중) → 순찰`)
  ```
  Sequence("충전(대기 중)", memory=False)          # 매 tick NeedsCharge 재검사
    ├─ NeedsCharge
    └─ Sequence("충전 왕복", memory=True)           # 진행은 잃지 않음
         = dock_leg("(대기)") + [DOCK_RETURN, ChargeDone(rewind=True)]
  ```
  손이 빈 것은 구조로 보장된다 — 회수 처리 · 캐리어 처리(얼어붙음 포함, Freeze 는 RUNNING)가 둘 다 FAILURE 일 때만 여기 온다. ChargeDone 이 타이머를 리셋하면 다음 tick 에 NeedsCharge 가 FAILURE → 가지가 닫히고 순찰(START 캐시 → POSE → PATROL)로 돌아간다.
- **START 뒤 `MarkDeparted`** — `Sequence("출발", [start_leaf, MarkDeparted])` 를 OneShot 안에.

### 5-4. `TaskManager` 노드 변경

| 항목 | 내용 |
|---|---|
| 액션 클라이언트 | `self.dock = ActionClient(self, Dock, "/docking/dock")` — **절대이름** |
| 파라미터 | `frames_yaml` · `soft_threshold_s`(900) · `hard_threshold_s`(0, 파라미터만 있고 동작 없음 — 설정되면 경고) · `charge_duration_s`(60, DOCK 잎 timeout 계산용) |
| 속성 | `dock_pose`, `dock_approach_m` (← `_resolve_dock_pose()`), `_departed_at`(monotonic, None = 출발 전) |
| 메서드 | `_resolve_dock_pose()` frames.yaml 읽기 · `mark_departed()` · `charge_done()` · `uptime_s()` · `needs_charge()` · `_docking_now()` · `log_charge(msg)` (Dock feedback 10% 마다 로그) |
| `_on_task_goal` | `self.failed` 다음에 `elif self._docking_now(): why = "docking: …"` → REJECT. 조건은 (1) DOCK_* 가 RUNNING 이거나 (2) 타이머 초과 + 미션 밖(다음 tick 에 B 가 열린다) |
| `_recover_ok_now` | `needs_charge()` 면 False — CREEP_OUT/RETURN 중이라도 RECOVER 를 받지 않는다(받으면 회수 가지가 도킹을 가로챈다) |
| `_state_string` | `uptime_s=NNN` 과, 타이머가 넘었으면 `charge_due=True` 토큰 추가(웹 · 로그용. 모르는 필드는 carrier_code_reader 도 웹도 무시) |

## 6. launch — `mission_nodes.launch.py`

- **전역 `docking_server` 1개** 추가 (event_logger 와 같은 자리, 네임스페이스 없음). `docking_server:=false` 인자로 끌 수 있다(둘째 launch 용).
- task_manager 파라미터에 `soft_threshold_s` · `hard_threshold_s` · `charge_duration_s` 전달 (`_docking_params()`). 도크 좌표는 넘기지 않는다(frames.yaml).
- docking_server 파라미터 `charge_duration_s` (`_docking_server_params()`). ★ task_manager 와 **같은 값**이어야 한다 — DOCK 잎 timeout 이 이 값 + 60 s.
- 상수: `SOFT_THRESHOLD_S = 900.0` · `HARD_THRESHOLD_S = 0.0` · `CHARGE_DURATION_S = 60.0`

## 7. 웹 — 충전 중 거절 처리

### backend `web/backend/app/services/dispatcher.py`
- `_last_state[robot_id]` — `robot.state` 채널에서 마지막 `state=` 값을 기억(메모리, 저장 안 함).
- `_docking(robot_id)` — 그 값이 `dock` 으로 시작하면 충전 중. `_peer_of(robot_id)` — 상대 로봇.
- `run()` — 충전 중인 로봇에게는 큐에서 꺼내 보내지 않는다(안 그러면 2초마다 보냄→거절→되돌림 반복).
- `task.rejected` — 충전 중이면 **경보 없이** 큐에 둔다. `RECOVER` 면 상대 큐 맨 앞으로 `queue.move_to_head()` 하고 상대를 깨운다(상대도 충전 중이면 그대로 둔다).
- `robot.state` — `dock*` 에서 벗어나는 순간 `wake(robot_id)` 로 밀린 작업을 바로 보낸다.

왜 상태 토픽으로 판정하나: ROS 액션의 goal 거절 응답에는 사유 문자열이 실리지 않는다. 그래서 task_manager 의 "docking:" 사유는 로봇 로그에만 남고, 웹은 `/orchestrator/state` 의 `state=dock*` 로 안다.

### backend `web/backend/app/services/queue.py`
- `move_to_head(task_id, robot_id)` — QUEUED 작업을 다른 로봇 큐의 맨 앞으로. `patch()` 의 "QUEUED 만 옮긴다" 규칙을 탄다.

### frontend `web/frontend/src/pages/MonitoringPage.jsx` · `App.css`
- `getStateClass` 에 `DOCK` 포함 → `charging` 클래스(초록 배지). 상태 문자열은 그대로 표시된다(`DOCK_NAV` · `DOCK` …).

## 8. 한 사이클이 실제로 어떻게 흐르나

1. 기동. robot1 START 출발 → `MarkDeparted` → 타이머 0 부터. robot2 는 60 s 뒤 출발, 그때 자기 타이머 시작.
2. 순찰 → 감지 → PICK → 로더 → PLACE. 이 사이 타이머가 900 s 를 넘으면 `state=… | charge_due=True`.
3. PLACE 성공 → "복귀 경로": `NeedsCharge` SUCCESS → `DOCK_NAV`(Nav2, 대기점 (3.5, y, 0°)) → `DOCK_IN`(직진 2 m) → `DOCK`(/docking/dock, 60 s, charge_pct 0→100) → `DOCK_OUT`(후진 2 m) → `ChargeDone`(타이머 0) → `RETURN`(Nav2 → patrol_route[0]) → 사이클 완료(웹 작업 success) → 순찰.
4. 그 사이 웹이 SCAN goal 을 보내면 로봇이 거절, 웹은 `state=dock*` 를 보고 경보 없이 큐에 둔다. RECOVER 였다면 상대 로봇 큐 맨 앞으로.
5. 캐리어를 못 만나고 순찰만 15분 돌았으면 "충전(대기 중)" 가지가 순찰을 밀어내고 3 과 같은 왕복을 한다(마지막이 `DOCK_RETURN`).

## 9. 검증한 것 / 못 한 것

**했다 (이 컨테이너, ROS 없이)**
- `task_manager.py` · `docking_server.py` · launch · web 백엔드 컴파일.
- rclpy · 인터페이스 스텁 + 실제 `py_trees` 로 `TaskManager()` 를 생성해 트리를 조립 — 우선순위 `[회수 처리, 캐리어 처리, 충전(대기 중), 작업 있나?]`, 두 dock_leg 한 벌씩, "복귀 경로" 자식 순서 확인.
- 타이머를 16분 뒤로 돌려 tick → `state=dock_nav | uptime_s=960 | charge_due=True`, DOCK_NAV 목표 (3.5, -6.591) 확인. 그 상태에서 SCAN · RECOVER goal 이 REJECT 되는 것, `charge_done()` 뒤 가지가 닫히고 순찰로 돌아가는 것 확인.
- `docking_server._execute` — 성공 · UNKNOWN_ROBOT · 두 goal 병렬(0.5 s, 직렬이면 1.0 s) · 취소(CANCELED, charge_pct 유지) 확인.
- 기존 단위테스트 `test_robot_command.py` 14개 통과.

**못 했다 (Isaac + ROS 환경에서 봐야 한다)**
- `colcon build` (Dock.action 생성 · cobot3_docking 설치).
- 실제 주행: DOCK_NAV 의 Nav2 goal 이 옆자리 상대가 주차된 상태에서 수락되는지, `patrol_to` 후진(DOCK_OUT)이 2 m 를 정확히 되짚는지, 도크 구역에서 회전이 정말 안 일어나는지.
- 두 대가 거의 동시에 도킹할 때의 Nav2 상호 회피.
- 웹: dispatcher 의 RECOVER 이관 경로(DB 필요).
