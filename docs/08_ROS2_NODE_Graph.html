03인터페이스 5개

확정된 필드 그대로다. cobot3_interfaces 에 들어 있다.

보내는 노드 → 받는 노드이름 · 타입 · 종류담는 것
carrier_code_reader → task_manager/perception/carrier_scan
CarrierScan · 토픽		header · payload(QR 원문 str) · qr_pose(Pose)
task_manager → nav_server/navigation/navigate_to
NavigateTo · 액션		goal pose / result success·fail_reason / fb distance_remaining_m
task_manager → pick_place_server/manipulation/pick_carrier
PickCarrier · 액션		goal variant · qr_pose(prior) / fb phase(OBSERVE…STOW)
task_manager → pick_place_server/manipulation/place_carrier
PlaceCarrier · 액션		goal variant 하나 / fb phase(MOVE…RETREAT)
task_manager → event_logger/trace/event
TraceEvent · 토픽		stamp · carrier_id · stage · success · fail_reason · port

goal 이 왜 이렇게 작은가

  • NavigateTo 는 좌표 하나. "shelf_1_s3" 같은 이름을 좌표로 푸는 건 task_manager 가 frames.yaml 을 보고 한다. 주행 노드는 이름을 모른다.
  • PickCarrier 는 종류 + 대략 위치. qr_pose 는 파지 목표가 아니라 flange_topview 가 플랜지를 찾을 탐색 창을 잡는 prior 다. 진짜 파지점은 플랜지를 위에서 재서 pnp 가 정한다 — 라벨이 옆벽이라 QR 자세만으로는 yaw 가 1σ 2.3도로 흔들린다(grasp.yaml flange_vision.why).
  • PlaceCarrier 는 종류 하나. 놓을 자리가 종류로 정해져 있다 — 매거진은 패키징 스테이션 로더, 스택은 테스트 스테이션 로더. 좌표는 place.yaml 에서 pnp 가 찾는다.
  • 튜닝값은 전부 노드 파라미터. 흡착 갭 · 접근 거리 · 컵 지름 · 허용오차 · 배치 높이 — goal 에 없다. 각 .action 파일 맨 위 ★ 블록에 어느 노드가 무엇을 declare_parameter 해야 하는지 적혀 있다.
아직 안 정해진 것

① place.yaml — 로더 좌표가 미정이라 파일이 아직 없다. 파라미터 자리만 잡아 뒀다. ② 배치 정밀도 — 12_place_test.py 의 허용오차는 위치 2 mm 인데 그 테스트는 베이스를 텔레포트해 주차 오차가 0이었다. 실주행 위치추정 오차는 2~5 cm 라 포트에 마커가 없으면 이 간극이 남는다. 로더 구조가 정해질 때 다시 본다. ③ 주차 실패 재시도 — NavigateTo 가 TOLERANCE_NOT_MET 으로 알리지만, 재시도 로직은 넣지 않았다.
