# 시연 영상 편집 프롬프트 — 레퍼런스(Piece Picking System) 스타일

> 레퍼런스: `Piece Picking System` 시연 영상 (60 s · 1280×720 · 30 fps · BGM only)
> 용도: 단위별 촬영 클립(start / patrol / pick / …)을 보내면서 이 프롬프트를 같이 붙여
> AI 영상 편집 도구·편집자·LLM(편집 스크립트 생성)에 전달한다.
> 아래 `[ ]` 는 클립을 보낼 때 채우는 자리다.

---

## 0. 레퍼런스 영상 분석 (프롬프트의 근거)

### 전체 구조 — 60초, 6개 블록

| 구간 | 블록 | 길이 | 내용 |
|---|---|---|---|
| 0–3 s | **인트로** | 3 s | 어두운 배경 위에 타이틀 → 부제 → 시나리오 카드 4개 → 입력 방식 칩 순서로 페이드인 |
| 4–15 s | **시나리오 01** | 12 s | (a) 시나리오 카드 + 웹 콘솔 화면, 명령어 타이핑 → (b) 로봇 실사 + 콘솔 분할 화면, 스텝 자막 → (c) 하이라이트 클로즈업 → (d) 완료 배지 |
| 16–27 s | **시나리오 02** | 12 s | 01과 동일 구조, 입력만 음성(STT)으로 변주 |
| 28–38 s | **시나리오 03** | 11 s | 동일 구조, 하이라이트 "까다로운 파지 자세" |
| 39–53 s | **시나리오 04** | 15 s | 동일 구조, 여러 물체를 연속 Pick/Place, "6개 스텝 모두 완료" |
| 54–57 s | **데이터 섹션** | 3 s | 작업 로그 표 → 학습 데이터 갤러리 → 3단계 리스트 + 파이프라인 칩 |
| 57–60 s | **아웃트로** | 3 s | 타이틀 재등장 + 시나리오 썸네일 4장 + 한 줄 슬로건 |

핵심: **시나리오마다 같은 4단 템플릿(카드 → 분할 화면 → 하이라이트 → 완료 배지)을 반복**한다.
반복 때문에 시청자가 두 번째 시나리오부터는 화면 구조를 안 읽고 내용만 본다.

### 시나리오 블록의 4단 템플릿

1. **시나리오 카드 (2–3 s)** — 좌측: `01 —— HOME` 같은 모노스페이스 번호 라벨, 큰 제목, 한 줄 설명, `작업 지시 · 타이핑 명령` 배지, 명령어가 타자 애니메이션으로 찍힘. 우측: 웹 콘솔 스크린샷(입력창이 민트색 테두리로 강조). 명령이 전송되면 좌측 아래에 `객체 인식 → 대상 선택 → 파지점 생성` 체크리스트가 순서대로 켜진다.
2. **분할 화면 (5–8 s)** — 좌 2/3: 로봇 실사(약간 크롭). 우 1/3: `WEB CONSOLE` 라벨을 단 콘솔 패널(카메라·깊이맵·인식 목록·로그). 우측 하단: 현재 명령문 인용. 화면 하단 좌: `STEP 04` 라벨 + `Pick` 큰 글자 + 부제(`스프레이 캔 파지`). 화면 하단 우: `PROCESS` 진행 바(5개 점, 완료=체크, 현재=민트 링, `STEP 04 / 05`). 스텝이 바뀔 때마다 자막과 진행 바만 갱신되고 레이아웃은 고정.
3. **하이라이트 (1–2 s)** — 풀스크린 클로즈업(파지 순간). 우상단 `↗ REPLAY · 확대 화면` 태그, 하단 좌 `HIGHLIGHT` 라벨 + `정밀 파지 자세` 제목 + 부제. 슬로우 또는 리플레이.
4. **완료 배지 (1 s)** — 실사 위에 `✓ 02 약국 작업 완료` + 요약(`음성명령 → 타이레놀정 → 왼쪽 박스`). 진행 바는 `COMPLETE`.

### 스타일

- **색**: 배경 짙은 남색·차콜(#0f1a1c 근처), 텍스트 흰색, 포인트 민트(#3fe0b0 근처) 하나만. 완료 체크·진행 바·제목 밑줄·입력창 테두리가 전부 같은 민트.
- **타이포**: 영문 타이틀 굵은 산세리프(Inter/Pretendard 계열), 한글 제목 굵게, 라벨은 작은 대문자 모노스페이스 자간 넓게(`AI VISION · COLLABORATIVE ROBOT`, `STEP 03`, `WEB CONSOLE`, `PROCESS`).
- **모션**: 페이드+살짝 위로 슬라이드(0.3 s). 카드→분할 화면 전환은 실사가 블러 상태에서 선명해지며 들어옴. 컷 사이 검은 화면 없음. 크로스 디졸브만 사용.
- **오디오**: BGM만(잔잔한 일렉트로닉, 컷 포인트에 맞춰 리듬). 나레이션 없음. 로봇 동작음은 살짝만.
- **화면 내 설명은 전부 자막·라벨로 처리**한다. 사람이 나오지 않는다. 배경 사람은 블러.

## 1. 우리 프로젝트에 맞춘 매핑

레퍼런스는 "자연어 명령 → 인식 → Pick → Place" 였다. 우리는 **AMR(Nova Carter) + M0609 협동로봇이 Isaac Sim 팹에서 선반을 순찰하다 QR 캐리어를 발견해 집어 로더로 이송**하는 시스템이다. 레퍼런스의 축을 다음처럼 바꾼다.

| 레퍼런스 | 우리 영상 |
|---|---|
| 타이틀 `Piece Picking System` | `[타이틀]` (제안: **AMR Carrier Transfer System** / 부제 `순찰 · QR 판독 · Pick & Place · 다중 로봇 조율`) |
| 상단 라벨 `AI VISION · COLLABORATIVE ROBOT` | `ISAAC SIM · MOBILE MANIPULATOR` |
| 시나리오 4개(가정/약국/재활용/통합) | 시나리오 = 미션 단계 묶음 (아래 §2) |
| 웹 콘솔(카메라·깊이·인식 목록) | 우리 관제 웹(`web/frontend`): MonitoringPage(공장 탑뷰·로봇 상태) / ProcessFlowPage / LogsPage / TaskAssignmentPage |
| 명령어 타이핑 | `/orchestrator/state` 값 변화 또는 웹 작업 배정(ExecuteTask) |
| 진행 바 5단계 (작업 지시→객체 인식→파지점 생성→Pick→Place) | **진행 바 7단계: 순찰 → 감지·정지 → QR 판독 → Pick → 이송 → Place → 복귀** (`patrol → hold → scan → pick → nav → place → returning`) |
| 데이터 섹션(작업 로그·학습 데이터) | 트레이스 DB(`magazine_log` / `stack_log`, append-only) + `patrol_records/` 순찰 사진 + LogsPage |

### 단위 클립 ↔ 진행 바 매핑 (클립 보낼 때 이 이름으로)

| 클립 이름 | 트리 단계(`state=`) | 진행 바 칸 | 자막 (STEP 제목 / 부제) |
|---|---|---|---|
| `start` | `start_wait → start → pose` | (인트로 뒤, 진행 바 앞) | `Start` / `시작 자리 → 순찰 시작점 · 관측 자세` |
| `patrol` | `patrol` | 1 순찰 | `Patrol` / `선반 정차점 사이 왕복 · QR 폴링` |
| `hold` | `hold` | 2 감지·정지 | `Hold` / `QR 감지 → 그 자리에 정지` |
| `scan` | `scan` | 3 QR 판독 | `Scan` / `캐리어 종류 · 위치 판독 (F1-MGZB-1)` |
| `pick` | `pick` | 4 Pick | `Pick` / `흡착 컵 Ø50 · 매거진 파지` |
| `nav` | `return_to_start → nav` (또는 `hold_back → approach → wait → push`) | 5 이송 | `Nav` / `로더로 주행` 또는 `상대 로봇 대기 · 우회` |
| `place` | `creep_in → place → creep_out` | 6 Place | `Place` / `로더 벨트에 배치` |
| `return` | `returning` | 7 복귀 | `Return` / `순찰 시작 좌표 복귀` |
| `stack` (선택) | `unloader_wait → stack_nav → stack_scan → stack_pick → stack_retreat → stack_deliver → stack_place` | 별도 시나리오 | `Recover` / `스택 회수 → 검사 스테이션` |
| `web` (선택) | ExecuteTask 배정 화면 녹화 | 시나리오 카드 우측 | — |

## 2. 최종 프롬프트 (복사해서 사용)

```
당신은 로봇 시연 영상 편집자다. 아래 스펙대로 60초 내외 시연 영상을 편집(또는 편집 스크립트/타임라인을 생성)하라.
첨부한 단위 클립은 파일명이 곧 단계 이름이다: [start.mp4, patrol.mp4, pick.mp4, ...].

■ 출력 규격
- 1920×1080(또는 1280×720) · 16:9 · 30 fps · 총 55–65 s · BGM만, 나레이션 없음.
- 배경 #0F1A1C, 텍스트 #FFFFFF, 포인트 색 #3FE0B0 하나만 사용. 체크·진행 바·밑줄·강조 테두리 전부 포인트 색.
- 영문 타이틀은 굵은 산세리프(Inter/Pretendard), 한글은 Pretendard Bold, 라벨은 소형 대문자 모노스페이스(자간 +10%).
- 전환은 크로스 디졸브 0.3 s 또는 페이드+위로 12 px 슬라이드. 검은 화면 컷 금지. 실사는 블러(12 px)에서 선명으로 들어온다.
- 화면에 사람이 나오면 블러 처리. 모든 설명은 자막·라벨로만.

■ 영상 구조 (레퍼런스와 동일한 6블록)
[0] 인트로 3 s
   상단 소형 라벨 "ISAAC SIM · MOBILE MANIPULATOR" → 타이틀 "[타이틀]" (밑에 포인트 색 짧은 밑줄) → 부제 "순찰 · QR 판독 · Pick & Place · 다중 로봇 조율" → 시나리오 카드 4개(01 순찰 감지 / 02 Pick & 이송 / 03 다중 로봇 조율 / 04 스택 회수·웹 배정) → 하단 칩 "작업 지시 방식: 자동 순찰 · 웹 배정" 순서로 0.4 s 간격 페이드인.

[1]~[4] 시나리오 블록 각 11–15 s. 모든 시나리오는 같은 4단 템플릿을 반복한다.
   (a) 시나리오 카드 2–3 s — 좌: "01 —— PATROL" 라벨, 제목, 한 줄 설명, 배지 "작업 지시 · 자동 순찰". 우: 관제 웹 스크린샷(입력·상태 영역에 포인트 색 테두리). state 문자열이 타자 애니메이션으로 찍힌다: "state=patrol detected=False". 전송 후 좌하단 체크리스트가 순서대로 켜진다.
   (b) 분할 화면 5–8 s — 좌 2/3 로봇 클립, 우 1/3 "WEB CONSOLE" 패널(공장 탑뷰·로봇 상태·로그). 우하단에 현재 state 인용("state=pick"). 하단 좌 STEP 라벨+제목+부제. 하단 우 "PROCESS" 진행 바 7칸: 순찰 → 감지·정지 → QR 판독 → Pick → 이송 → Place → 복귀. 완료=체크, 현재=포인트 색 링, "STEP n / 07". 클립이 바뀌어도 레이아웃은 고정하고 자막·진행 바만 갱신.
   (c) 하이라이트 1–2 s — 풀스크린 클로즈업(파지 순간·QR 판독 순간·두 로봇이 교차하는 순간). 우상단 "↗ REPLAY · 확대 화면", 하단 좌 "HIGHLIGHT" 라벨 + 제목 + 부제. 0.5배속 리플레이.
   (d) 완료 배지 1 s — 실사 위에 "✓ 01 순찰 감지 완료" + 요약("순찰 → QR 감지 → 정지 → 판독"). 진행 바는 COMPLETE.

   시나리오별 내용:
   01 순찰 감지 (클립: start, patrol, hold, scan)
      STEP Start "시작 자리 → 순찰 시작점 · 관측 자세" / Patrol "선반 정차점 사이 왕복 · QR 폴링" / Hold "QR 감지 → 그 자리에 정지" / Scan "캐리어 종류·위치 판독 (F1-MGZB-1)"
      하이라이트: QR 판독 순간 (손목 RSD455 화면 + 정지한 로봇)
      완료 배지: "01 순찰 감지 완료 · 선반 [n] → [캐리어 코드]"
   02 Pick & 이송 (클립: pick, nav, place, return)
      STEP Pick "흡착 컵 Ø50 · 매거진 파지" / Nav "순찰 시작점 복귀 후 로더로 주행" / Place "로더 벨트에 배치 (creep in/out)" / Return "순찰 시작 좌표 복귀"
      하이라이트: 흡착 파지 순간 클로즈업
      완료 배지: "02 이송 완료 · [캐리어 코드] → 로더 [이름]"
   03 다중 로봇 조율 (클립: 두 로봇이 같이 보이는 클립 — hold_back / wait / push)
      STEP Hold Back "픽업존 대기 · 상대가 로더에 멈출 때까지" / Wait "대기 장소 · 로더가 비기를 기다린다" / Push "차선이 비면 로더로 진입"
      하이라이트: 두 로봇이 로더 차선에서 교차하지 않고 순서대로 들어가는 탑뷰
      완료 배지: "03 조율 완료 · 로더 차선 1대씩 · 교착 없음"
   04 스택 회수 · 웹 배정 (클립: web, stack)
      (a) 카드의 우측은 TaskAssignmentPage 녹화 — RECOVER 작업이 큐에 올라 배차되는 화면
      STEP Recover "패키지 언로더 → 스택 집기 → 검사 스테이션" / Deliver "대기점 후퇴 후 Nav2 주행" / Place "검사 투입구 배치"
      하이라이트: 스택 QR 판독 → 파지
      완료 배지: "04 회수 완료 · 웹 배정 → 스택 → 검사 스테이션"

[5] 데이터 섹션 3 s
   좌: "DATA COLLECTION" 라벨, 제목 "작업 로그 및 트레이스 DB", 3단계 리스트(① TraceEvent 자동 기록 — 단계·시각·물체 상태 / ② append-only 로그 축적 — magazine_log · stack_log / ③ 관제 화면과 배차에 활용 — LogsPage · pending_pickup). 아래 파이프라인 칩: "작업 수행 → /trace/event → event_logger → PostgreSQL → 웹".
   우: LogsPage 표 → patrol_records 사진 갤러리 → ProcessFlowPage 순으로 0.8 s 간격 교체.

[6] 아웃트로 3 s
   타이틀 재등장 + 시나리오 썸네일 4장(각 하이라이트 프레임, 하단에 01~04 라벨) + 슬로건 "[슬로건]" (제안: "순찰에서 이송까지, 사람 개입 없이 · 모든 단계가 기록으로 남는다").

■ 클립 사용 규칙
- 각 단위 클립은 가장 동작이 잘 보이는 3–6 s만 쓴다. 대기 구간은 잘라내거나 2배속.
- 로봇이 멈춰 있는 hold / wait 클립은 2 s 이내로 짧게, 대신 자막으로 "왜 멈췄는지"를 쓴다.
- 클립 하나가 여러 단계를 담고 있으면 state 문자열이 바뀌는 시점에 자막·진행 바를 갱신한다.
- 스크린 녹화(웹)는 1.5배 확대해 텍스트가 읽히게 하고, 포인트 색 테두리로 볼 곳을 표시한다.
- 빠진 클립이 있으면 해당 STEP을 건너뛰지 말고 자막만 짧게(0.8 s) 띄운 뒤 다음 클립으로 넘어간다.
```
