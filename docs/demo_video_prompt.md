# 시연 영상 편집 프롬프트 — 레퍼런스(Piece Picking System) 스타일, 느린 호흡판

> 레퍼런스: `Piece Picking System` 시연 영상 (60 s · 1280×720 · 30 fps · BGM only)
> 용도: 단위별 촬영 클립 8개 + 도킹 클립을 보내면서 이 프롬프트를 같이 붙여
> AI 영상 편집 도구·편집자·LLM(편집 스크립트 생성)에 전달한다.
> `[ ]` 는 클립을 보낼 때 채우는 자리다.
>
> v2 변경: 레퍼런스(60 s)는 너무 짧고 정신없다. **총 2분 30초 안팎으로 늘리고, 한 화면에
> 한 가지만 보여 준다.** 원본 클립은 기본 **3배속**, 움직임이 작은 구간은 더 가속하고,
> 챕터와 관련된 구간만 잘라 쓴다. 단위는 8개 + 도킹 1개.

## 0. 레퍼런스에서 가져오는 것 / 버리는 것

레퍼런스 분석(60 s = 인트로 3 s → 시나리오 4개 × 12 s → 데이터 3 s → 아웃트로 3 s)은
`git log` 의 이전 판 문서를 보면 된다. 여기서는 결론만 적는다.

| 가져온다 | 버린다 |
|---|---|
| 색·타이포·모션 (짙은 남색 배경, 민트 포인트 하나, 모노스페이스 라벨, 페이드+슬라이드) | 12초 안에 4단계를 욱여넣는 밀도 |
| 챕터 카드 → 분할 화면 → 하이라이트 → 완료 배지의 **4단 템플릿** | 시나리오 하나에 STEP 자막이 1~2초마다 바뀌는 것 |
| 하단 `PROCESS` 진행 바 | 5칸 → **8칸**(우리 단위) |
| 우측 1/3 `WEB CONSOLE` 패널 | 카메라·깊이맵 → 관제 웹(공장 탑뷰·state·로그) |
| 데이터 섹션·아웃트로 썸네일 | — |
| — | 자연어 명령 축. 우리는 자동 순찰 + 웹 배정 |

호흡 원칙 세 가지.

1. **챕터 하나 = 단위 클립 하나.** 챕터 안에서 STEP 자막은 안 바뀐다. 진행 바만 챕터 시작에 한 칸 켜진다.
2. **화면에 동시에 뜨는 글자는 세 덩어리 이하.** (STEP 자막 · 진행 바 · 콘솔 패널) 완료 배지가 뜰 때는 STEP 자막을 내린다.
3. **컷 최소.** 챕터당 컷 3~4개(카드 → 본 클립 → 하이라이트 → 배지). 본 클립 안에서는 컷 대신 속도로 길이를 조절한다.
4. **클립은 챕터에 맞는 구간만.** 원본 하나가 여러 단계를 담고 있어도 그 챕터의 단계에 해당하는 구간만 잘라 쓴다. 나머지는 다른 챕터에서 쓰거나 버린다.
5. **움직임이 곧 속도.** 로봇이 크게 움직이는 구간은 3배속, 팔·베이스가 거의 안 움직이는 구간(대기·판독·크립·정렬)은 6~8배속. 속도 변화는 램프(0.5 s)로 부드럽게.
6. **가속해도 3 s 넘게 멈춰 있으면 잘라 버린다.** 자막으로 메우지 않는다. 앞뒤를 디졸브로 잇는다.

## 1. 단위 클립 ↔ 챕터 매핑

원본 클립은 기본 **3배속**, 움직임 작은 구간은 **6~8배속**. 아래 "화면 길이"는 가속 적용 후 목표 길이이고,
이 길이에 맞추기 위해 **챕터와 관련 없는 앞뒤 구간은 잘라낸다.**

| # | 클립 이름 | 트리 단계(`state=`) | 진행 바 칸 | STEP 제목 / 부제 | 화면 길이 |
|---|---|---|---|---|---|
| 01 | `start` | `start_wait → start → pose` | ① 시작 | `Start` / `시작 자리 → 순찰 시작점 · 팔 관측 자세` | 8–10 s |
| 02 | `patrol` | `patrol → hold → scan` | ② 순찰 | `Patrol` / `선반 정차점 왕복 · QR 감지 → 정지 · 판독` | 10–12 s |
| 03 | `pick` | `pick` | ③ Pick | `Pick` / `흡착 컵 Ø50 · 매거진 파지` | 8–10 s |
| 04 | `return_to_start` (픽 후 순찰선으로 빠져나오기) | `return_to_start` | ④ 순찰선 복귀 | `Return to Route` / `좁은 통로에서 순찰 시작점까지 후진 · Nav2 전 안전 지점 확보` | 6–8 s |
| 05 | `nav` (place 하러 이동) | `nav` (또는 `hold_back → approach → wait → push`) | ⑤ 이송 | `Nav` / `Nav2 로 로더까지 주행` (두 로봇이면 `상대 로봇 대기 · 차선 1대씩`) | 10–12 s |
| 06 | `place` | `creep_in → place → creep_out` | ⑥ Place | `Place` / `벨트 쪽 크립 진입 → 로더에 배치 → 후진` | 8–10 s |
| 07 | `stack_pick` | `unloader_wait → stack_nav → stack_scan → stack_pick → stack_retreat` | ⑦ 스택 Pick | `Stack Pick` / `패키지 언로더에서 스택 판독 · 파지 · 대기점 후퇴` | 10–12 s |
| 08 | `stack_place` | `stack_deliver → stack_place` | ⑧ 스택 Place | `Stack Place` / `검사 스테이션까지 주행 · 투입구에 배치` | 8–10 s |
| 09 | `docking` | `returning → dock` (docking_server) | 진행 바 밖 · 별도 챕터 | `Docking` / `배터리 임계 → dock_pad 접근 · 접점 결합 · 충전 대기` | 12–15 s |

챕터 09는 "NEW" 배지를 달고 진행 바 대신 `DOCKING SYSTEM` 라벨을 쓴다.
매거진 사이클(01~06)과 스택 회수(07~08)와 별개인 **로봇 자체 유지** 기능이라는 뜻이다.

## 2. 최종 프롬프트 (복사해서 사용)

```
당신은 로봇 시연 영상 편집자다. 아래 스펙대로 약 2분 30초짜리 시연 영상을 편집(또는 편집 스크립트/타임라인을 생성)하라.
첨부한 클립은 파일명이 곧 챕터 이름이다:
[start.mp4, patrol.mp4, pick.mp4, return_to_start.mp4, nav.mp4, place.mp4, stack_pick.mp4, stack_place.mp4, docking.mp4]
+ 웹 관제 화면 녹화 [web.mp4] (선택)

■ 절대 규칙
- 원본 로봇 클립은 기본 3배속. 로봇이 크게 움직이는 구간(주행·팔 이동·파지·배치)은 3배속, 거의 안 움직이는 구간(대기·QR 판독·크립·정렬·충전)은 6~8배속. 속도 전환은 0.5 s 램프.
- 클립 전체를 쓰지 않는다. 그 챕터의 단계에 해당하는 구간만 잘라 쓴다(예: pick.mp4에 순찰 끝부분이 섞여 있으면 팔이 내려가기 직전부터). 챕터와 무관한 앞뒤는 버린다.
- 잘라낸 뒤 가속해서 목표 길이(챕터당 본 클립 8–12 s)에 맞춘다. 그래도 15 s를 넘으면 멈춤 구간을 먼저 잘라 버리고, 그 다음 움직임 작은 구간을 더 가속한다.
- 가속 후에도 로봇이 3 s 넘게 멈춰 있는 구간은 잘라서 버린다. 자막으로 설명하지 않는다. 멈춤 앞뒤를 크로스 디졸브 0.5 s로 이어 붙인다.
- 챕터 하나 = 클립 하나. 챕터 안에서 STEP 자막은 바뀌지 않는다.
- 한 화면에 글자 덩어리 3개 이하. 자막은 최소 3 s 이상 머문다.
- 전환은 크로스 디졸브 0.5 s. 검은 화면 컷 금지. 실사는 블러(12 px)에서 선명으로 들어온다.
- 나레이션 없음. BGM은 느린 템포(80–95 BPM)의 잔잔한 일렉트로닉. 로봇 동작음은 -18 dB로 깔기만.
- 화면에 사람이 보이면 블러.

■ 규격·스타일
- 1920×1080 · 16:9 · 30 fps · 총 2:20–2:40.
- 배경 #0F1A1C, 텍스트 #FFFFFF, 포인트 색 #3FE0B0 하나만. 체크·진행 바·밑줄·강조 테두리 전부 포인트 색.
- 영문 제목 Inter Bold, 한글 Pretendard Bold, 라벨은 소형 대문자 모노스페이스(자간 +10%).
- 모션은 페이드 + 위로 12 px 슬라이드 0.4 s. 요소는 0.5 s 간격으로 하나씩 들어온다.

■ 고정 레이아웃 (모든 챕터 공통)
- 좌 2/3: 로봇 클립. 우 1/3: "WEB CONSOLE" 라벨을 단 관제 웹 패널(공장 탑뷰·로봇 state·트레이스 로그). 웹 녹화가 없으면 스크린샷 한 장을 고정으로 두고 state 값만 텍스트로 갱신한다.
- 우측 패널 하단: 현재 state 인용 한 줄 ("state=pick detected=True").
- 하단 좌: "STEP 03" 라벨 + 큰 제목 "Pick" + 부제 한 줄.
- 하단 우: "PROCESS" 진행 바 8칸 — 시작 → 순찰 → Pick → 순찰선 복귀 → 이송 → Place → 스택 Pick → 스택 Place. 완료=체크, 현재=포인트 색 링, "STEP n / 08".

■ 타임라인

[0] 인트로 — 8 s
   0.0 s  상단 소형 라벨 "ISAAC SIM · MOBILE MANIPULATOR"
   0.5 s  타이틀 "[타이틀]" (제안: AMR Carrier Transfer System), 아래 포인트 색 짧은 밑줄
   1.5 s  부제 "순찰 · QR 판독 · Pick & Place · 스택 회수 · 도킹"
   3.0 s  챕터 카드 5개 가로 나열: 01 Start / 02 Patrol / 03 Pick & Return / 04 Nav & Place / 05 Stack / + 06 Docking (NEW 배지)
   5.0 s  하단 칩 "작업 지시 방식: 자동 순찰 · 웹 배정 (RECOVER)"

   (b) 본 클립 8–12 s — 고정 레이아웃. 챕터 시작에 진행 바가 한 칸 켜진다. 그 뒤로는 아무 자막도 안 바뀐다. 클립이 3배속이라 로봇이 충분히 움직이므로 글자로 더 설명하지 않는다.

[10] 데이터 섹션 — 8 s
   좌: "DATA COLLECTION" 라벨, 제목 "작업 로그 및 트레이스 DB", 리스트 3개가 1 s 간격으로 들어온다:
      ① TraceEvent 자동 기록 — 단계 · 시각 · 물체 상태
      ② append-only 로그 축적 — magazine_log · stack_log
      ③ 관제와 배차에 활용 — LogsPage · pending_pickup
   아래 파이프라인 칩: 작업 수행 → /trace/event → event_logger → PostgreSQL → 웹
   우: LogsPage 표 → patrol_records 사진 갤러리 → ProcessFlowPage, 각 2.5 s 홀드.

[11] 아웃트로 — 8 s
   타이틀 재등장 → 챕터 썸네일 6장(01~06 Docking, 각 하이라이트 프레임) 1 s 간격 → 슬로건 "[슬로건]" (제안: "순찰에서 이송, 회수, 충전까지 — 사람 개입 없이, 모든 단계가 기록으로 남는다") → 2 s 홀드 → 페이드아웃.

■ 예상 길이
   인트로 8 + 챕터 8개 × 16 = 128 + 도킹 20 + 데이터 8 + 아웃트로 8 ≈ 172 s (2:52).
   2:40을 넘으면 하이라이트를 먼저 줄이고, 그래도 넘으면 챕터 카드를 3 → 2 s로 줄인다. 본 클립은 줄이지 않는다.

■ 클립 사용 규칙
- 가속 기준: 화면 안에서 로봇의 움직임 크기로 판단한다. 베이스가 주행하거나 팔이 크게 움직이면 3배속, 제자리 대기·판독·미세 정렬은 6~8배속. 가속 후에도 3 s를 넘게 멈춰 있는 구간은 잘라서 버린다. 멈춤 앞 1 s와 뒤 1 s만 남기고 디졸브로 잇는다. 멈춘 이유가 시연에 중요하면(예: 상대 로봇에게 로더 차선 양보) 잘라낸 자리에 자막 대신 완료 배지 요약에 한 마디 넣는다.
- 챕터 관련 구간만 사용: 원본 하나에 여러 단계가 들어 있으면 그 챕터의 state 구간만 쓴다. 우측 패널의 state 인용을 기준으로 시작·끝을 잡는다.
- 하이라이트에 쓸 "순간"은 가속하지 않은 원본에서 따로 뽑는다(0.5배속 리플레이).
- 클립 하나에 state 가 여러 번 바뀌어도 STEP 자막은 그대로 두고, 우측 패널의 state 인용 한 줄만 갱신한다.
- 웹 녹화는 1.5배 확대해 텍스트가 읽히게 하고 포인트 색 테두리로 볼 곳을 표시한다.
- 빠진 클립이 있으면 그 챕터는 카드 3 s + 배지 2 s만 두고 넘어간다.
```
