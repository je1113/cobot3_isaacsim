# 시연 영상 편집 프롬프트 — 단위 클립 잘라 붙이기 + 챕터 자막

> 레퍼런스: `Piece Picking System` 시연 영상 (60 s · 1280×720 · 30 fps · BGM only)
> 용도: 단위별 촬영 클립 8개 + 도킹 클립을 보내면서 이 프롬프트를 같이 붙여
> AI 영상 편집 도구·편집자·LLM(편집 스크립트 생성)에 전달한다.
> `[ ]` 는 클립을 보낼 때 채우는 자리다.
>
> 레퍼런스에서 가져오는 것은 **단위별로 잘라 챕터로 묶고, 챕터마다 STEP 자막·진행 상태·완료 표시를
> 다는 방식** 하나다. 레퍼런스의 색·폰트·BGM·전환·속도감은 따라 하지 않는다.
> 색은 우리 영상(Isaac Sim 공장 씬, 밝은 고키 톤)의 실제 프레임에서 뽑는다 — §1-1 팔레트. 나머지 디자인은 편집자 재량.
> 원본 클립은 기본 3배속, 움직임이 작은 구간은 더 가속하고, 챕터와 관련된 구간만 잘라 쓴다.
> 단위는 8개 + 도킹 1개. **총 길이는 정하지 않는다** — 보내 준 클립을 잘라내고 가속한 결과가 곧 타임라인이다.

## 0. 레퍼런스에서 가져오는 것 / 버리는 것

레퍼런스 분석(60 s = 인트로 3 s → 시나리오 4개 × 12 s → 데이터 3 s → 아웃트로 3 s)은
`git log` 의 이전 판 문서를 보면 된다. 여기서는 결론만 적는다.

| 가져온다 (구조·자막) | 안 가져온다 (디자인·속도) |
|---|---|
| 단위 클립 하나 = 챕터 하나로 잘라 붙이는 방식 | 색·폰트·모션·BGM·전환 효과 |
| 챕터 카드 → 본 클립 → 하이라이트 → 완료 표시의 **4단 순서** | 12초 안에 4단계를 욱여넣는 속도감 |
| 챕터마다 STEP 제목 + 부제 자막 | STEP 자막이 1~2초마다 바뀌는 것 |
| 진행 상태 표시 (레퍼런스 5칸 → 우리 **8칸**) | 자연어 명령 축. 우리는 자동 순찰 + 웹 배정 |
| 관제 화면을 옆에 두는 것 | 카메라·깊이맵 내용 |
| 마지막 데이터 섹션 + 아웃트로 썸네일 | — |

자르기 원칙.

1. **챕터 하나 = 단위 클립 하나.** 챕터 안에서 STEP 자막은 안 바뀐다. 진행 바만 챕터 시작에 한 칸 켜진다.
2. **화면에 동시에 뜨는 글자는 세 덩어리 이하.** (STEP 자막 · 진행 바 · 콘솔 패널) 완료 배지가 뜰 때는 STEP 자막을 내린다.
3. **챕터당 컷 3~4개**(카드 → 본 클립 → 하이라이트 → 완료 표시).
4. **클립은 챕터에 맞는 구간만.** 원본 하나가 여러 단계를 담고 있어도 그 챕터의 단계에 해당하는 구간만 잘라 쓴다. 나머지는 다른 챕터에서 쓰거나 버린다.
5. **움직임이 곧 속도.** 로봇이 크게 움직이는 구간은 3배속, 팔·베이스가 거의 안 움직이는 구간(대기·판독·크립·정렬)은 6~8배속.
6. **가속해도 3 s 넘게 멈춰 있으면 잘라 버린다.** 자막으로 메우지 않는다.

## 1. 단위 클립 ↔ 챕터 매핑

원본 클립은 기본 **3배속**, 움직임 작은 구간은 **6~8배속**. 챕터와 관련 없는 앞뒤 구간과 3 s 넘는 멈춤은 잘라낸다.
**그러고 남은 길이가 그 챕터의 길이다.** 목표 초 수는 없다.

| # | 클립 이름 | 트리 단계(`state=`) | 진행 바 칸 | STEP 제목 / 부제 |
|---|---|---|---|---|
| 01 | `start` | `start_wait → start → pose` | ① 시작 | `Start` / `시작 자리 → 순찰 시작점 · 팔 관측 자세` |
| 02 | `patrol` | `patrol → hold → scan` | ② 순찰 | `Patrol` / `선반 정차점 왕복 · QR 감지 → 정지 · 판독` |
| 03 | `pick` | `pick` | ③ Pick | `Pick` / `흡착 컵 Ø50 · 매거진 파지` |
| 04 | `return_to_start` (픽 후 순찰선으로 빠져나오기) | `return_to_start` | ④ 순찰선 복귀 | `Return to Route` / `좁은 통로에서 순찰 시작점까지 후진 · Nav2 전 안전 지점 확보` |
| 05 | `nav` (place 하러 이동) | `nav` (또는 `hold_back → approach → wait → push`) | ⑤ 이송 | `Nav` / `Nav2 로 로더까지 주행` (두 로봇이면 `상대 로봇 대기 · 차선 1대씩`) |
| 06 | `place` | `creep_in → place → creep_out` | ⑥ Place | `Place` / `벨트 쪽 크립 진입 → 로더에 배치 → 후진` |
| 07 | `stack_pick` | `unloader_wait → stack_nav → stack_scan → stack_pick → stack_retreat` | ⑦ 스택 Pick | `Stack Pick` / `패키지 언로더에서 스택 판독 · 파지 · 대기점 후퇴` |
| 08 | `stack_place` | `stack_deliver → stack_place` | ⑧ 스택 Place | `Stack Place` / `검사 스테이션까지 주행 · 투입구에 배치` |
| 09 | `docking` | `returning → dock` (docking_server) | 진행 바 밖 · 별도 챕터 | `Docking` / `배터리 임계 → dock_pad 접근 · 접점 결합 · 충전 대기` |

챕터 09는 "NEW" 배지를 달고 진행 바 대신 `DOCKING SYSTEM` 라벨을 쓴다.
매거진 사이클(01~06)과 스택 회수(07~08)와 별개인 **로봇 자체 유지** 기능이라는 뜻이다.

### 1-1. 색 팔레트 — 영상 안에 있는 색만 쓴다

실제 클립 프레임(1~5번)에서 뽑았다. **렌더는 밝은 고키 톤이다** — 화면의 96%가 흰색~밝은 회색이고,
어두운 색은 로더 벨트·모니터의 짙은 청록뿐이다. 그래서 그래픽도 밝은 바탕을 기본으로 하고,
자막·패널만 씬의 짙은 청록으로 얹는다. 이 표 밖의 색은 쓰지 않는다.

| 용도 | 색 | 어디서 온 색인가 |
|---|---|---|
| 인트로·카드·데이터·아웃트로 배경 | `#E0E3E1` | 바닥·벽 (화면의 42%) |
| 배경 위 2단계 면 (카드 박스, 썸네일 테두리) | `#D4D6D5` / `#BFC4C4` | 선반 상판, 바닥 그림자 |
| 비활성 진행 바 칸, 구분선 | `#AFB5B4` | 선반 프레임 |
| 보조 글자 (밝은 바탕 위) | `#606562` | 로봇 바퀴·그림자 짙은 곳 |
| 자막·패널 배경 (85% 불투명), 밝은 바탕 위 제목 글자 | `#2C474C` | 로더 벨트·모니터의 짙은 청록 |
| 패널 안 글자 | `#E0E3E1` | 바닥색 그대로 |
| **강조 1 — 현재 단계 링, 강조 테두리, 제목 밑줄** | `#68A7B1` | 스테이션·주차 패드의 청록 경계선 (하늘색 역할) |
| **강조 2 — 완료 체크, 링크·숫자** | `#446890` | 매거진 라벨의 강청색 (파란색 역할) |

규칙.

- 강조는 청록 `#68A7B1`(현재)과 강청 `#446890`(완료) 둘. 둘 다 씬에 있는 색이다. 민트·초록·노랑·빨강은 쓰지 않는다.
- 갈색·주황(매거진 상자 `#9B8661`, `#7F6642`, 콘)은 로봇이 다루는 물체 색이라 **그래픽에는 쓰지 않는다.**
- 검은색 순색은 쓰지 않는다. 가장 어두운 색은 `#2C474C`. 영상에 순검정이 없어서 순검정을 얹으면 튄다.
- 인트로·카드 배경은 단색 `#E0E3E1` 대신 **로봇 클립을 밝게(흰색 `#E0E3E1` 60%) 덮어 깔아도 된다.** 씬 톤 그대로라 가장 안전하다.
- 관제 웹은 따뜻한 흰색 바탕(`#FAF9F7`)이라 씬의 차가운 흰색과 미묘하게 다르다. 테두리를 `#AFB5B4`로 둘러 "화면"임을 표시하면 어색하지 않다.

## 2. 최종 프롬프트 (복사해서 사용)

```
당신은 로봇 시연 영상 편집자다. 아래 스펙대로 시연 영상을 편집(또는 편집 스크립트/타임라인을 생성)하라.
총 길이는 정해져 있지 않다. 첨부 클립을 아래 규칙대로 잘라내고 가속한 결과가 곧 타임라인이다.
첨부한 클립은 파일명이 곧 챕터 이름이다:
[start.mp4, patrol.mp4, pick.mp4, return_to_start.mp4, nav.mp4, place.mp4, stack_pick.mp4, stack_place.mp4, docking.mp4]
+ 웹 관제 화면 녹화 [web.mp4] (선택)

■ 절대 규칙
- 원본 로봇 클립은 기본 3배속. 로봇이 크게 움직이는 구간(주행·팔 이동·파지·배치)은 3배속, 거의 안 움직이는 구간(대기·QR 판독·크립·정렬·충전)은 6~8배속.
- 클립 전체를 쓰지 않는다. 그 챕터의 단계에 해당하는 구간만 잘라 쓴다(예: pick.mp4에 순찰 끝부분이 섞여 있으면 팔이 내려가기 직전부터). 챕터와 무관한 앞뒤는 버린다.
- 잘라내고 가속한 뒤 남은 길이가 그 챕터의 본 클립 길이다. 목표 초 수에 맞추려고 더 자르거나 늘리지 않는다.
- 가속 후에도 로봇이 3 s 넘게 멈춰 있는 구간은 잘라서 버린다. 자막으로 설명하지 않는다.
- 챕터 하나 = 클립 하나. 챕터 안에서 STEP 자막은 바뀌지 않는다.
- 한 화면에 글자 덩어리 3개 이하. 자막은 최소 3 s 이상 머문다.
- 나레이션 없음. 설명은 전부 자막으로.
- 화면에 사람이 보이면 블러.

■ 규격
- 1920×1080 · 16:9 · 30 fps. 총 길이는 클립이 정한다.
- 색은 영상 안에 있는 색만 쓴다. 영상은 밝은 고키 톤이다. 배경 #E0E3E1 / 2단계 면 #D4D6D5·#BFC4C4 / 비활성 칸·구분선 #AFB5B4 / 보조 글자 #606562 / 자막·패널 배경 #2C474C (85% 불투명, 씬의 짙은 청록) / 패널 안 글자 #E0E3E1 / 강조(현재 단계·테두리) #68A7B1 청록 / 강조(완료 체크) #446890 강청.
- 민트·초록·노랑·빨강·순검정 금지. 갈색·주황은 영상 속 매거진·콘 색이라 그래픽에는 쓰지 않는다.
- 관제 웹 화면은 #AFB5B4 테두리를 둘러 "화면"임을 표시한다.
- 카드·인트로 배경은 단색 대신 로봇 클립을 밝게(#E0E3E1 60%) 덮어 깔아도 된다.
- 폰트·전환·BGM·모션은 편집자 재량. 아래에 적은 것은 "무엇을 어디에 띄우는가"이지 디자인 지시가 아니다.

■ 화면에 띄우는 것 (모든 챕터 공통)
- 로봇 클립이 주가 되고, 옆이나 구석에 관제 웹 화면(공장 탑뷰·로봇 state·트레이스 로그)을 작게 둔다. 웹 녹화가 없으면 스크린샷 한 장을 고정으로 두고 state 값만 텍스트로 갱신한다.
- 현재 state 한 줄 ("state=pick detected=True").
- STEP 번호 + 제목 (예: "STEP 03 · Pick") + 부제 한 줄.
- 진행 상태 8칸 — 시작 → 순찰 → Pick → 순찰선 복귀 → 이송 → Place → 스택 Pick → 스택 Place. 완료·현재·미완료가 구분되게. "STEP n / 08".

■ 타임라인

   띄울 글자, 순서대로: 소형 라벨 "ISAAC SIM · MOBILE MANIPULATOR" → 타이틀 "[타이틀]" (제안: AMR Carrier Transfer System) → 부제 "순찰 · QR 판독 · Pick & Place · 스택 회수 · 도킹" → 챕터 목록 01 Start / 02 Patrol / 03 Pick & Return / 04 Nav & Place / 05 Stack / 06 Docking (NEW) → "작업 지시 방식: 자동 순찰 · 웹 배정 (RECOVER)".

■ 클립 사용 규칙
- 가속 기준: 화면 안에서 로봇의 움직임 크기로 판단한다. 베이스가 주행하거나 팔이 크게 움직이면 3배속, 제자리 대기·판독·미세 정렬은 6~8배속. 가속 후에도 3 s를 넘게 멈춰 있는 구간은 잘라서 버린다. 멈춤 앞 1 s와 뒤 1 s만 남기고 잇는다. 멈춘 이유가 시연에 중요하면(예: 상대 로봇에게 로더 차선 양보) 잘라낸 자리에 자막 대신 완료 배지 요약에 한 마디 넣는다.
- 챕터 관련 구간만 사용: 원본 하나에 여러 단계가 들어 있으면 그 챕터의 state 구간만 쓴다. 우측 패널의 state 인용을 기준으로 시작·끝을 잡는다.
- 하이라이트에 쓸 "순간"은 가속하지 않은 원본에서 따로 뽑는다(0.5배속 리플레이).
- 클립 하나에 state 가 여러 번 바뀌어도 STEP 자막은 그대로 두고, 우측 패널의 state 인용 한 줄만 갱신한다.

- 빠진 클립이 있으면 그 챕터는 카드 3 s + 배지 2 s만 두고 넘어간다.
```
