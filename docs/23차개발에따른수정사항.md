### 새 레이아웃의 확정값

```
매거진 x  = -2.4408 / -1.8642 / -1.2396 / -0.6408   (양쪽 선반 동일)

  SHELF-B  x -0.6408 → -2.4408,  y = -1.0636,  theta = π   (진행 방향이 뒤집힌다)

로봇 스폰 / AMCL 초기자세
```

### B-1. `SHELF_ZONE` 🔴 지금 QR 이 한 개도 안 읽힌다

> ⏸️ **값은 나중에 직접 정한다.** 아래는 그때 참고할 배경이다 —
> 이 항목 때문에 다른 작업을 멈출 필요는 없다.

**이게 무엇인가.** 맵 좌표에 그어 둔 사각형 하나다. "지금 로봇이 선반 앞에 있나"를
`amcl_pose` 로 판정한다.

```python
SHELF_ZONE_X = (-7.10, -4.40)
SHELF_ZONE_Y = (1.00, 1.65)
```

**누가 읽나.** 두 노드가 같은 값을 **각자 복제해서** 들고 있다.

| 노드 | 줄 | 하는 일 |
|---|---|---|
| `carrier_code_reader.py` | 92–93, 164 | 이 안에서만 팔을 관측 자세로 뻗고 QR 을 폴링한다. 밖이면 팔을 내린다(disarm) |
| `nav_server.py` | 94–95, 134 | 이 안에서는 `SHELF_DRIVE_MAX_V`(0.12 m/s)로 기어간다. 빠르면 흔들려서 디코드가 깨진다 |

`nav_server.py:89-93` 주석에 *"carrier_code_reader 의 SHELF_ZONE_X/Y 와 **반드시 같아야
한다** — 스캔 구역과 저속 구역이 같은 자리를 가리켜야 한다"* 고 적혀 있다.

**무엇이 깨졌나.** 저 사각형이 옛 레이아웃 값이다.

```
사각형:  x -7.10 ~ -4.40     y  1.00 ~ 1.65
실제:    x -2.44 ~ -0.64     y  2.0364(A) / -1.0636(B)
```

x 가 겹치는 구간이 **하나도 없다.** `_in_shelf_zone()` 이 항상 False 라
`carrier_detected` 가 한 번도 안 뜨고, 선반 앞 감속도 안 걸린다.
순찰 가지를 되살려도 QR 을 한 개도 못 본다.

**왜 숫자만 바꾸면 안 되나.** 선반이 둘이고 통로를 사이에 두고 마주본다.
로봇이 서는 y 가 `+2.0364`(A) 와 `-1.0636`(B) 로 갈라져 있어서, 한 사각형으로 둘을
다 덮으면 **그 사이 통로 전체가 "선반 앞"** 이 된다 — 통로를 지날 때마다 팔을 뻗고
0.12 m/s 로 기어간다.

**선택지**

| | 내용 | 대가 |
|---|---|---|
| 사각형 2개로 하드코딩 | 간단하다 | 복제가 4곳(2노드 × 2존)으로 늘어난다 |
| `shelves.yaml` 에서 파생 *(권장)* | `waypoint_start/end` + `standoff_distance` 가 이미 그 사각형을 정의한다 | 선반을 옮기면 따라오고, 두 파일의 복제도 같이 없어진다 |

지금 깨진 원인이 정확히 "`shelves.yaml` 만 옮기고 상수는 안 옮겼다" 라서 두 번째를 권한다.

### B-7. `POSE_BY_PATROL_TARGET`
